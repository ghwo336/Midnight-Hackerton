# 데모 진행표

**읽는 사람: 데모를 직접 돌리는 사람.** 발표장에서든 녹화 중이든, 이 문서만
보고 순서대로 따라갈 수 있게 적는다. 제품 설명은 [README](../README.md) 에
있고 여기에는 **무엇을 누르고 무엇이 뜨는지**만 적는다.

---

## 0. 두 갈래 중 무엇을 쓸 것인가

| | 로컬 회로 | Preprod |
|---|---|---|
| 준비물 | 없음 | Lace 지갑, DUST, 발급 기관 키 |
| 한 건에 걸리는 시간 | 1초 미만 | **30~45초** |
| tx 해시 | 시뮬레이터가 붙인 번호 | 진짜. 탐색기가 열린다 |
| 되돌리기 | `/devtools` 의 데모 초기화 | **불가능** |

**기본은 로컬이다.** 이야기 전체를 로컬로 보여주고, 마지막에 Preprod 로
넘어가 "같은 것이 실제 체인에 올라가 있다" 를 20초쯤 보여주는 구성이
제일 안전하다. 화면 상단에 `local-circuit` / `preprod` 가 그대로 뜨므로
모드를 숨기지 말고 오히려 짚어준다.

Preprod 로 전체를 돌리면 3분짜리 데모에서 80초가 대기로 날아간다.

## 1. 시작 전 점검

### 로컬 회로

```bash
pnpm install     # 처음 한 번
pnpm dev         # API 3011 / 웹 3040
```

- [ ] `http://localhost:3040` 이 열린다
- [ ] 상단에 **`local-circuit`** 이 뜬다
- [ ] `/devtools` → **데모 초기화** 를 눌러 채권 3건을 미사용으로 되돌렸다
- [ ] 납품업체 화면에 채권 3건이 보이고 전부 미사용이다

루트에 `.env` 가 있으면 안 된다. 있으면 `pnpm dev` 도 Preprod 로 붙는다.
preprod 설정은 `.env.preprod` 에 두고 `pnpm dev:preprod` 로만 켠다.

**판정 기준은 하나다 — 상단에 `local-circuit` 이 뜨는가.** 파일이 있나 없나를
눈으로 세지 말고 화면을 봐라.

### Preprod

`pnpm dev:preprod` 로 띄운다. `.env.preprod` 에 `CHAIN_MODE=preprod`,
`CONTRACT_ADDRESS`, `DEPLOY_BLOCK` 이 있어야
한다. 값은 [`apps/deploy/deployment.json`](../apps/deploy/deployment.json) 에 있다.

- [ ] 상단에 **`preprod`** 와 실제 블록 높이가 뜬다
- [ ] `/devtools` 에서 지갑이 연결되고 **DUST 잔액이 0 이 아니다**
- [ ] `/devtools` → 발급 기관 키 → 원장의 공개키가 보인다
- [ ] 납품업체 화면에 미사용 채권이 **최소 1건** 있다

DUST 가 0 이면 트랜잭션이 나가지 않는다. tNIGHT 잔액이 있어도 그렇다.
DUST 는 NIGHT 보유량에서 시간에 따라 생성되고, 등록이 돼 있어야 쌓인다.

## 2. 로컬 회로 진행표 (2분)

| # | 할 일 | 화면에 뜨는 것 | 가리킬 곳 |
|---|---|---|---|
| 1 | `/console` 을 연다 | 납품업체·금융사 A·금융사 B 세 화면과 아래 공개 원장 | 세 화면이 서로를 모른다는 것 |
| 2 | 금융사 A 화면을 먼저 읽는다 | 예치 잔액 10억, 대출 0건 | **없는 것**: 구매기업명·채권번호·승인번호 |
| 3 | 납품업체에서 채권 #1 을 클릭 | 왼쪽에 파란 선 | 액면 1억, 담보 한도 8천만 |
| 4 | 제공 정보 체크박스를 본다 | 신용등급·지급 시기·업종 세 개뿐 | **구매기업명은 선택지에 없다** |
| 5 | 금융사 A 행의 **신청** | A 에 `지급 완료` 도장, 예치 잔액 9억 2천만 | 잔액이 줄어든 것 |
| 6 | 채권 #1 을 다시 클릭 | 신청 버튼이 **꺼지고** `이미 사용된 채권입니다 · 금융사 A · 블록 N` | 금융사 B 는 A 의 장부를 본 적이 없는데 막혔다. **이 판정은 공개 원장에서 온다** |
| 7 | 조건 비교표의 예치 잔액 | A 9억 2천만, **B 10억 그대로** | 두 번째 대출은 나갈 길이 없다 |
| 8 | 아래 공개 원장 | 중복확인값·금융사·금액·봉인값·순번·tx·시각 | **채권 내용이 한 글자도 없다** |

여기까지가 이야기 전부다. 6번 한 프레임이 제품이고 나머지는 그 프레임을
이해시키는 준비다.

> **예전 진행표와 다른 점.** 예전에는 6번에서 B 의 신청을 눌러 거부 도장과
> `assert` 로그를 보여줬다. 지금은 사용된 채권의 신청 버튼이 꺼진다
> (c51dc39 — 누를 수 있게 두면 "가능하다" 고 말해 놓고 거부해서 고장처럼
> 보인다). 그래서 **"회로가 막았다" 는 증거는 아래 공격 재현에서 보여준다.**
> 예전 진행표는 [archive/DEMO.2026-09-26.md](archive/DEMO.2026-09-26.md).

### 이어서 공격 (30초) — "서버가 아니라 회로가 막았다"

`/console` **하단 공격 시나리오 줄**에서 A1~A6 을 차례로 누른다 (로컬 모드에서만
보인다. `/devtools` 에도 같은 러너가 있다). 각 칸에
판정·거부 코드·나간 자금이 뜬다.

| 누를 것 | 뜨는 것 | 말할 것 |
|---|---|---|
| A1 파일명·인코딩 변경 | `통과` · `NULLIFIER_ALREADY_USED` · 나간 자금 0 | 파일을 바꿔도 중복확인값은 같다. 회로의 `assert(!usedNullifiers.member(nf))` 에서 걸렸다 |
| A2 새 salt 로 재봉인 | `통과` · `NULLIFIER_ALREADY_USED` · 0 | 봉인값을 바꿔도 중복확인값은 같다 |
| A3 액면 부풀리기 · A4 타인 채권 | `통과` · `ISSUER_ATTESTATION_FAILED` · 0 | 발급 기관이 등록한 채권과 맞지 않는다 |
| **A5 두 금융사 동시 신청** | `통과` · `NULLIFIER_ALREADY_USED` · 나간 자금 **4천만** | **클라이맥스.** 동시에 냈는데 한 건만 확정됐다 |
| A6 지연 제출 | `통과` · `NULLIFIER_ALREADY_USED` · 0 | 이미 쓰인 뒤에 낸 신청은 막힌다 (로컬 한계는 아래) |

- **`통과` 는 "방어가 통과했다" = 공격이 막혔다는 뜻이다.** 초록색이다.
  보는 사람이 "공격이 통과했다" 로 읽지 않게 한 번 짚어준다.
- A5 만 나간 자금이 0 이 아니다. 정상 대출 1건분이 나간 것이고, 그게 맞다.
  A5 는 **첫 미사용 채권**을 쓴다. 5번에서 #1 을 썼으면 #2(한도 4천만)라서
  4천만이 뜬다. 미사용 채권이 없으면 아무 일도 일어나지 않는다 — 데모 초기화.
- **로컬 A6 는 "미리 준비" 를 재현하지 않는다.** 사용된 채권으로 다시 내는
  것이라 A1 과 거의 같다. 미리 만든 증명을 나중에 내는 진짜 시험은 실제 체인
  재현기(§3.4)에서만 일어난다. 로컬 결과로 "실행 시점 재검사를 증명했다" 고
  말하지 않는다.
- 이 러너는 **로컬 회로 결과**다. 실제 체인 결과라고 말하지 않는다 (§6).

### 녹화 전 체크

- [ ] `/console` 하단 공격 줄의 **데모 초기화** 를 누른다 (`/devtools` 탭은 열지 않는다)
- [ ] `localhost:3040` 탭은 `/console` **하나만** 연다 (§5 "증명 생성에서 멈춘다")
- [ ] `/console` 을 새로고침했다
- [ ] `/` (지갑 진입 화면) 은 쓰지 않는다. 한 번에 한 역할만 보여서 6번 프레임이 안 나온다
- [ ] 브라우저 **전체화면(F11)**, 확대 **100%**. 첫 화면에 세 역할 화면이 꽉 차고, 아래로
  스크롤하면 공개 원장과 공격 줄이 나온다. 원장을 짚을 때(§2 8번)와 공격 때 페이지를 내린다
- [ ] 납품업체 화면은 칸 안에서 스크롤한다. 신청 버튼(조건 비교표)과 실행 로그가 보이게
  미리 위치를 잡아 둔다

## 3. Preprod 진행표 (5분)

로컬과 순서는 같다. 다른 점만 적는다.

### 3.1 한 건에 30~45초가 걸린다

버튼을 누르면 구간이 화면에 계속 뜬다. 멈춘 게 아니다.

| 구간 | 무엇을 기다리는가 |
|---|---|
| 준비 중 | 프로바이더 구성, 컨트랙트 접속 |
| 증명 생성 중 | proof server 왕복 |
| 지갑 승인 대기 | **사람이 Lace 창을 눌러야 한다** |
| 트랜잭션 제출 중 | 노드에 넣는다 |
| 블록 확정 대기 | 블록에 들어갈 때까지 |

실측한 것은 두 가지다. **한 건 전체가 29.5~44.5초**, 그중 **증명이
0.64~1.37초** (배포 때 7회, [deployment.json](../apps/deploy/deployment.json)).
나머지를 승인과 블록이 나눠 갖는데 둘을 따로 재지는 않았다.

말할 수 있는 것은 이것이다: **증명은 1초 남짓이고 시간의 대부분은 승인과
블록이다.** 발표에서 "영지식 증명이 느리다" 로 읽히지 않게 한 번 짚어준다.

증명은 브라우저 CPU 가 아니라 proof server 에서 일어난다. 클라이언트는
증명키(`finance.prover` 는 10MB)를 실어 보낸다.

### 3.2 진짜라는 것을 보여주는 곳

1. 상단에 `preprod` 와 실제 블록 높이
2. 공개 원장의 tx 해시를 누르면 탐색기가 열린다
   `https://preprod.midnightexplorer.com/transactions/<해시>`
3. 컨트랙트 주소도 같은 탐색기에서 열린다

배포 자체의 증거(8건의 초기 설정 트랜잭션)는 README §5 표에 있다.
발표에서 8건을 하나씩 보여줄 이유는 없다.

### 3.3 채권 예산 — 미리 세어 둘 것

**Preprod 채권은 쓰면 되돌릴 수 없다.** 중복 확인값이 원장에 영구히
남는다. 그게 이 제품이 주장하는 바로 그 성질이라 초기화 경로를 두지 않았다.

| 하는 일 | 소모 |
|---|---|
| 정상 데모 (신청 1건 + 중복 거절) | 채권 1건 |
| A5 동시 신청 | 채권 1건 |
| A6 지연 제출 | 채권 1건 |

**원본(`52a72d93…`) 미사용 채권은 2건이다** (2026-09-26 A6 가 수정 전에
원본에서 한 번 돌아 1건 소모). A5·A6 를 원본에서 처음 누르지 마라.
리허설은 연습용 컨트랙트에서 한다 — `/devtools` [배포 시작] 으로 올리고
`pnpm dev:rehearsal` 로 띄운다 ([DEPLOY.md §1.6](DEPLOY.md)). 원본 채권은
한 장도 쓰지 않는다.

**컷 3 (Preprod 증거) 에는 새 트랜잭션이 필요 없다.** 원본에 이미 실제
대출이 있으니 그 tx 링크를 열면 된다. 채권을 쓰지 않는다.

떨어지면 `/issuer` 에서 발급한다. 지갑 승인 1회, 30~45초. 그 기기에
발급 기관 비밀키가 있어야 한다 (§4 참조).

### 3.4 A5·A6 를 실제 체인에서 돌리려면

`/devtools` → **실제 체인 공격 재현**. 각각 지갑 승인 2회다.

판정이 세 갈래인 것을 알아 두면 좋다.

- **통과** — 한 건만 확정되고, 진 쪽을 회로가 중복 확인값으로 막았다
- **실패** — 두 건 다 확정됐다 (이중 담보가 뚫렸다)
- **판정 불가** — 진 쪽이 회로에 닿기 전에 죽었다 (승인 거부, 잔액 조정 실패)

지갑이 두 트랜잭션의 자금을 동시에 잡지 못해 **판정 불가가 나올 수 있다.**
그건 고장이 아니라 회로가 막았다는 증거가 없다는 뜻이다. 그때는 통과라고
말하지 않는다.

**A6 (지연 제출) 는 2026-09-26 에 고쳤다 (f897232).** 그 전에는 지연 제출이
서버 사전 검사에서 걸려 **체인에 한 번도 나가지 않았고** 늘 판정 불가였다.
지금은 미사용 시점에 증명까지 만들어 두고, lender-a 확정 뒤에 그대로
제출한다. 판정은:

- 체인이 블록에 넣되 컨트랙트 호출 세그먼트만 실패시킴(`FailFallible`, 인덱서
  표기 `PARTIAL_SUCCESS`), 원장에 그 채권의 대출이 lender-a 1건뿐 → **통과**
- 2분 안에 블록에 안 들어감 → **판정 불가** (노드가 멤풀에서 버렸을 가능성)
- 셋업(lender-a)이 원장에 안 보이면 B 를 아예 내지 않는다 (채권만 잃는다, 695abc7)

`FailEntirely` 가 아니다. 컨트랙트 호출은 수수료(세그먼트 0)와 별도 세그먼트에
들어가서, 회로 검사 실패는 그 세그먼트만 실패시킨다. 처음엔 `FailEntirely` 로
예상했다가 실측으로 뒤집었다 (7263e71).

**연습용에서 통과했다 (2026-09-26, 연습용 `2eb10497…`, 채권 #3).**
A 블록 2714409 SUCCESS → B 블록 2714417 PARTIAL_SUCCESS, 컨트랙트 액션 0건,
lender-b 예치 그대로. 증거는 [TEST_REPORT.md §1](TEST_REPORT.md).
**원본에서는 아직 돌리지 않았다.** "실제 체인에서 A6 를 검증했다" 고 말할 때는
연습용 컨트랙트였다고 함께 말한다.

**A5 (동시 신청) 는 실제 체인에서 시연하지 않는다 — 단일 지갑으로는 불가.**
1am 은 같은 DApp 의 앞 트랜잭션이 끝나기 전에 다음 트랜잭션을 받지 않는다
(지갑 정책). 연습용 2(`33c8fc99…`)에서 5회 시도해 전부 판정 불가였고 채권은
쓰지 않았다 (대출 0건).

- 처음부터 동시에 (4회): 서명 요청 두 개가 한꺼번에 들어가 승인 불가,
  지갑 내부 오류 `r.identifiers is not iterable`
- 증명 먼저 + A 제출 후 B 제출 (1회): 1am 이 B 를 `Duplicate request` 로 거절

진 쪽이 막히는 메커니즘(실행 시점 재검사)은 A6 가 체인에서 증명했다. 비어 있는
것은 **합의 계층이 두 건의 순서를 정하는 부분**뿐이고, 그건 지갑 두 개가 있어야
시험할 수 있다. 기록은 [TEST_REPORT.md §1](TEST_REPORT.md) "A5 실제 체인 시도".

**발표에서 A5 는 로컬 모드(`pnpm dev`)의 `/devtools` 공격 시나리오로 보여준다**
(§2, `통과`). 실제 체인 재현 섹션의 시연 대상은 **A6 뿐**이다. A5 를 실제 체인에서
검증했다고 말하지 않는다.

## 4. 발급 기관 키

발급은 **배포한 브라우저에서만** 된다. 회로가
`assert(issuerPublicKey(issuerSecret()) == issuerPk)` 를 보고, 그 비밀키는
그 기기의 IndexedDB 에만 있다.

발표 기기가 배포 기기와 다르면 먼저 옮겨야 한다.

1. 배포 기기 `/devtools` → 발급 기관 키 → **키 내보내기**
2. 발표 기기 `/devtools` → **키 가져오기** → 파일 선택
3. 대조 결과가 **일치** 로 뜨는지 확인한다

불일치가 뜨면 그 기기로는 발급할 수 없다. 데모에 발급 단계가 없다면
그대로 진행해도 된다 — 신청·상환은 지갑만 있으면 된다.

**브라우저 데이터를 지우면 그 컨트랙트의 발급 권한이 영구히 사라진다.**
발표 전에 한 번 내보내 두는 것을 권한다.

## 5. 막혔을 때

| 증상 | 원인 | 할 일 |
|---|---|---|
| 화면 값이 전부 `—` | API 가 안 떠 있다 | 상단 "노드" 항목이 무엇이 안 됐는지 적는다 |
| `could not balance dust` | DUST 가 0 이다 | `/devtools` 에서 DUST 잔액 확인 |
| 지갑 창이 안 뜬다 | Lace 가 다른 창에 가려졌거나 잠겼다 | Lace 아이콘을 직접 누른다 |
| 3분이 넘게 "지갑 승인 대기" | 승인 창을 놓쳤다 | 화면이 3분에 그렇게 말한다 |
| `SERVER_CANNOT_SIGN` | Preprod 인데 서버 서명 경로로 갔다 | 정상 동작이다. 브라우저 경로 버튼을 쓴다 |
| `CLAIM_NOT_ON_CHAIN` | 인덱서가 아직 블록을 안 보여준다 | 서버가 2초 간격으로 세 번 다시 본다. 그래도 안 되면 잠시 뒤 다시 |
| 신청 버튼이 비활성 | 지갑 미연결이거나 미사용 채권이 없다 | 버튼 아래 문구가 어느 쪽인지 적는다 |
| 발급 버튼이 멈춘다 | 이 기기에 발급 기관 비밀키가 없다 | §4 |
| 공격 러너가 안 보인다 | Preprod 다 | 정상. 실제 체인 재현기가 대신 보인다 |
| 로컬인데 "증명 생성" 이 `대출 신청 접수` 에서 멈추고 초가 계속 올라간다 | 서버는 이미 확정했는데 화면이 단계 이벤트(SSE)를 못 받았다. 브라우저는 한 주소에 연결 6개까지만 여는데, 다른 `localhost:3040` 탭들이 스트림을 붙들고 있거나 API 재시작 전에 연 탭이다 | 다른 탭을 전부 닫고 `/console` 을 새로고침. 원장에 이미 들어갔으므로 도장이 맞게 뜬다 |
| 채권을 골랐는데 신청 버튼이 꺼져 있다 | 이미 사용된 채권이다 | 정상 (§2 6번). 미사용 채권을 고르거나 데모 초기화 |
| 대출 행의 tx 칸이 비어 있다 (Preprod) | 서버가 인덱서 이력을 아직 다 못 읽었다. 기동 후 수 초 걸린다 | 잠시 뒤 새로고침. 계속 비면 API 로그의 `대출 tx 이력 복원 실패` 를 본다 |

**로컬에서 응답이 10초 넘게 없으면** 증명이 느린 게 아니라 요청이 아예 못
나간 것이다. 로컬 실행은 1초 안에 끝난다.

## 6. 말하면 안 되는 것

데모에서 나오기 쉬운, 근거가 없는 문장들이다.

- **"A5·A6 를 실제 체인에서 검증했다"** — `/devtools` 에서 직접 눌러
  통과가 떴을 때만 할 수 있는 말이다. 안 눌렀으면 그건 시뮬레이터 결과다.
- **"금융사는 채권 내용을 전혀 모른다"** — 금융사는 심사하려고 납품업체에게
  원문을 받는다. 정확히는 **"금융사끼리 서로의 장부를 보지 않고도 중복을
  막는다"** 이다. 이쪽이 방어하기도 쉽고 공유 장부가 왜 안 굴러가는지와
  정확히 맞물린다.
- **"원장에 아무것도 안 올라간다"** — 중복 확인값·금융사·금액·봉인값은
  올라간다. 올라가지 않는 것은 **채권 내용** 이다.
- **배속 영상을 그대로 두는 것** — 쓰려면 화면에 적는다. 눈치채는 순간
  나머지 주장까지 의심받는다.
