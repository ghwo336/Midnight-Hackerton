# 데모 진행표

**읽는 사람: 데모를 직접 돌리는 사람.** 발표장에서든 녹화 중이든, 이 문서만
보고 순서대로 따라갈 수 있게 적는다. 제품 설명은 [README](../README.md) 에
있고 여기에는 **무엇을 누르고 무엇이 뜨는지**만 적는다.

---

## 0. 두 갈래 중 무엇을 쓸 것인가

| | 로컬 회로 | Preprod |
|---|---|---|
| 준비물 | 없음 | Lace 지갑, DUST, 발급 기관 키 |
| 한 건에 걸리는 시간 | 1초 미만 | **30~45초** |
| tx 해시 | 시뮬레이터가 붙인 번호 | 진짜. 탐색기가 열린다 |
| 되돌리기 | `/devtools` 의 데모 초기화 | **불가능** |

**기본은 로컬이다.** 이야기 전체를 로컬로 보여주고, 마지막에 Preprod 로
넘어가 "같은 것이 실제 체인에 올라가 있다" 를 20초쯤 보여주는 구성이
제일 안전하다. 화면 상단에 `local-circuit` / `preprod` 가 그대로 뜨므로
모드를 숨기지 말고 오히려 짚어준다.

Preprod 로 전체를 돌리면 3분짜리 데모에서 80초가 대기로 날아간다.

---

## 1. 시작 전 점검

### 로컬 회로

```bash
pnpm install     # 처음 한 번
pnpm dev         # API 3011 / 웹 3040
```

- [ ] `http://localhost:3040` 이 열린다
- [ ] 상단에 **`local-circuit`** 이 뜬다
- [ ] `/devtools` → **데모 초기화** 를 눌러 채권 3건을 미사용으로 되돌렸다
- [ ] 납품업체 화면에 채권 3건이 보이고 전부 미사용이다

`.env` 가 있으면 안 된다. 있으면 Preprod 로 붙는다.

### Preprod

`.env` 에 `CHAIN_MODE=preprod`, `CONTRACT_ADDRESS`, `DEPLOY_BLOCK` 이 있어야
한다. 값은 [`apps/deploy/deployment.json`](../apps/deploy/deployment.json) 에 있다.

- [ ] 상단에 **`preprod`** 와 실제 블록 높이가 뜬다
- [ ] `/devtools` 에서 지갑이 연결되고 **DUST 잔액이 0 이 아니다**
- [ ] `/devtools` → 발급 기관 키 → 원장의 공개키가 보인다
- [ ] 납품업체 화면에 미사용 채권이 **최소 1건** 있다

DUST 가 0 이면 트랜잭션이 나가지 않는다. tNIGHT 잔액이 있어도 그렇다.
DUST 는 NIGHT 보유량에서 시간에 따라 생성되고, 등록이 돼 있어야 쌓인다.

## 2. 로컬 회로 진행표 (2분)

| # | 할 일 | 화면에 뜨는 것 | 가리킬 곳 |
|---|---|---|---|
| 1 | `/console` 을 연다 | 납품업체·금융사 A·금융사 B 세 화면과 아래 공개 원장 | 세 화면이 서로를 모른다는 것 |
| 2 | 금융사 A 화면을 먼저 읽는다 | 예치 잔액 10억, 대출 0건 | **없는 것**: 구매기업명·채권번호·승인번호 |
| 3 | 납품업체에서 채권 #1 을 클릭 | 왼쪽에 파란 선 | 액면 1억, 담보 한도 8천만 |
| 4 | 제공 정보 체크박스를 본다 | 신용등급·지급 시기·업종 세 개뿐 | **구매기업명은 선택지에 없다** |
| 5 | 금융사 A 행의 **신청** | A 에 `지급 완료` 도장, 예치 잔액 9억 2천만 | 잔액이 줄어든 것 |
| 6 | 채권 #1 을 다시 클릭 → 금융사 B 행의 **신청** | B 에 `이미 사용` 도장 | **지급 금액 0, 예치 잔액 10억 그대로** |
| 7 | 실행 로그를 읽는다 | `거부 · assert: !usedNullifiers.member(nf)` | 우리 서버가 아니라 회로가 거부했다 |
| 8 | 아래 공개 원장 | 중복확인값·금융사·금액·봉인값·블록·tx·시각 | **채권 내용이 한 글자도 없다** |

여기까지가 이야기 전부다. 6번 한 프레임이 제품이고 나머지는 그 프레임을
이해시키는 준비다.

### 이어서 공격 (30초)

`/devtools` → A1~A6 을 차례로 누른다. 전부 `막힘`, 나간 자금 0.
**A5 가 클라이맥스다** — 한 채권에 두 금융사가 동시에 신청하는데 한쪽만
확정되고 다른 쪽 자금은 그대로다.

A5 만 나간 자금이 0 이 아니다. 정상 대출 1건분이 나간 것이고, 그게 맞다.

## 3. Preprod 진행표 (5분)

로컬과 순서는 같다. 다른 점만 적는다.

### 3.1 한 건에 30~45초가 걸린다

버튼을 누르면 구간이 화면에 계속 뜬다. 멈춘 게 아니다.

| 구간 | 무엇을 기다리는가 |
|---|---|
| 준비 중 | 프로바이더 구성, 컨트랙트 접속 |
| 증명 생성 중 | proof server 왕복 |
| 지갑 승인 대기 | **사람이 Lace 창을 눌러야 한다** |
| 트랜잭션 제출 중 | 노드에 넣는다 |
| 블록 확정 대기 | 블록에 들어갈 때까지 |

실측한 것은 두 가지다. **한 건 전체가 29.5~44.5초**, 그중 **증명이
0.64~1.37초** (배포 때 7회, [deployment.json](../apps/deploy/deployment.json)).
나머지를 승인과 블록이 나눠 갖는데 둘을 따로 재지는 않았다.

말할 수 있는 것은 이것이다: **증명은 1초 남짓이고 시간의 대부분은 승인과
블록이다.** 발표에서 "영지식 증명이 느리다" 로 읽히지 않게 한 번 짚어준다.

증명은 브라우저 CPU 가 아니라 proof server 에서 일어난다. 클라이언트는
증명키(`finance.prover` 는 10MB)를 실어 보낸다.

### 3.2 진짜라는 것을 보여주는 곳

1. 상단에 `preprod` 와 실제 블록 높이
2. 공개 원장의 tx 해시를 누르면 탐색기가 열린다
   `https://preprod.midnightexplorer.com/transactions/<해시>`
3. 컨트랙트 주소도 같은 탐색기에서 열린다

배포 자체의 증거(8건의 초기 설정 트랜잭션)는 README §5 표에 있다.
발표에서 8건을 하나씩 보여줄 이유는 없다.

### 3.3 채권 예산 — 미리 세어 둘 것

**Preprod 채권은 쓰면 되돌릴 수 없다.** 중복 확인값이 원장에 영구히
남는다. 그게 이 제품이 주장하는 바로 그 성질이라 초기화 경로를 두지 않았다.

| 하는 일 | 소모 |
|---|---|
| 정상 데모 (신청 1건 + 중복 거절) | 채권 1건 |
| A5 동시 신청 | 채권 1건 |
| A6 지연 제출 | 채권 1건 |

지금 미사용 채권은 3건이다. **리허설 예산이 없다.** 리허설은 로컬에서
하고 Preprod 는 본 공연에서만 쓴다.

떨어지면 `/issuer` 에서 발급한다. 지갑 승인 1회, 30~45초. 그 기기에
발급 기관 비밀키가 있어야 한다 (§4 참조).

### 3.4 A5·A6 를 실제 체인에서 돌리려면

`/devtools` → **실제 체인 공격 재현**. 각각 지갑 승인 2회다.

판정이 세 갈래인 것을 알아 두면 좋다.

- **통과** — 한 건만 확정되고, 진 쪽을 회로가 중복 확인값으로 막았다
- **실패** — 두 건 다 확정됐다 (이중 담보가 뚫렸다)
- **판정 불가** — 진 쪽이 회로에 닿기 전에 죽었다 (승인 거부, 잔액 조정 실패)

지갑이 두 트랜잭션의 자금을 동시에 잡지 못해 **판정 불가가 나올 수 있다.**
그건 고장이 아니라 회로가 막았다는 증거가 없다는 뜻이다. 그때는 통과라고
말하지 않는다.

## 4. 발급 기관 키

발급은 **배포한 브라우저에서만** 된다. 회로가
`assert(issuerPublicKey(issuerSecret()) == issuerPk)` 를 보고, 그 비밀키는
그 기기의 IndexedDB 에만 있다.

발표 기기가 배포 기기와 다르면 먼저 옮겨야 한다.

1. 배포 기기 `/devtools` → 발급 기관 키 → **키 내보내기**
2. 발표 기기 `/devtools` → **키 가져오기** → 파일 선택
3. 대조 결과가 **일치** 로 뜨는지 확인한다

불일치가 뜨면 그 기기로는 발급할 수 없다. 데모에 발급 단계가 없다면
그대로 진행해도 된다 — 신청·상환은 지갑만 있으면 된다.

**브라우저 데이터를 지우면 그 컨트랙트의 발급 권한이 영구히 사라진다.**
발표 전에 한 번 내보내 두는 것을 권한다.

## 5. 막혔을 때

| 증상 | 원인 | 할 일 |
|---|---|---|
| 화면 값이 전부 `—` | API 가 안 떠 있다 | 상단 "노드" 항목이 무엇이 안 됐는지 적는다 |
| `could not balance dust` | DUST 가 0 이다 | `/devtools` 에서 DUST 잔액 확인 |
| 지갑 창이 안 뜬다 | Lace 가 다른 창에 가려졌거나 잠겼다 | Lace 아이콘을 직접 누른다 |
| 3분이 넘게 "지갑 승인 대기" | 승인 창을 놓쳤다 | 화면이 3분에 그렇게 말한다 |
| `SERVER_CANNOT_SIGN` | Preprod 인데 서버 서명 경로로 갔다 | 정상 동작이다. 브라우저 경로 버튼을 쓴다 |
| `CLAIM_NOT_ON_CHAIN` | 인덱서가 아직 블록을 안 보여준다 | 서버가 2초 간격으로 세 번 다시 본다. 그래도 안 되면 잠시 뒤 다시 |
| 신청 버튼이 비활성 | 지갑 미연결이거나 미사용 채권이 없다 | 버튼 아래 문구가 어느 쪽인지 적는다 |
| 발급 버튼이 멈춘다 | 이 기기에 발급 기관 비밀키가 없다 | §4 |
| 공격 러너가 안 보인다 | Preprod 다 | 정상. 실제 체인 재현기가 대신 보인다 |

**로컬에서 응답이 10초 넘게 없으면** 증명이 느린 게 아니라 요청이 아예 못
나간 것이다. 로컬 실행은 1초 안에 끝난다.

## 6. 말하면 안 되는 것

데모에서 나오기 쉬운, 근거가 없는 문장들이다.

- **"A5·A6 를 실제 체인에서 검증했다"** — `/devtools` 에서 직접 눌러
  통과가 떴을 때만 할 수 있는 말이다. 안 눌렀으면 그건 시뮬레이터 결과다.
- **"금융사는 채권 내용을 전혀 모른다"** — 금융사는 심사하려고 납품업체에게
  원문을 받는다. 정확히는 **"금융사끼리 서로의 장부를 보지 않고도 중복을
  막는다"** 이다. 이쪽이 방어하기도 쉽고 공유 장부가 왜 안 굴러가는지와
  정확히 맞물린다.
- **"원장에 아무것도 안 올라간다"** — 중복 확인값·금융사·금액·봉인값은
  올라간다. 올라가지 않는 것은 **채권 내용** 이다.
- **배속 영상을 그대로 두는 것** — 쓰려면 화면에 적는다. 눈치채는 순간
  나머지 주장까지 의심받는다.

한계는 [TEST_REPORT.md §5](TEST_REPORT.md) 에 정리돼 있다. 질문이 그쪽으로
가면 거기를 열면 된다.
