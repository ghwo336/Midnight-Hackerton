# 인수인계 — 다음 개발자에게

**블록체인이 처음이어도 읽을 수 있게 썼다.**

`README.md`가 제품이 무엇이고 어떻게 실행하는지를 이미 설명한다. 이 문서는 README가 다루지 않는 것만 다룬다: **기술 스택, 환경을 처음부터 만드는 법, 지금 막혀 있는 것, 함정, 남은 작업.**

읽는 순서

```
1. README.md        제품이 뭔지, 왜 만들었는지, 어떻게 실행하는지
2. 이 문서           스택·환경 준비·인수인계 사항
3. docs/CONTEXT.md  판단이 갈릴 때 보는 기준
4. docs/SPEC.md     구현 명세
5. docs/DESIGN.md   화면 규칙
```

## 1. 제일 먼저 알아야 할 것

### 개발은 지갑 없이 시작한다

```bash
pnpm install
pnpm dev
```

이 두 줄이면 끝이다. **지갑도, 테스트넷 자금도, Compact 컴파일러도 필요 없다.**

그런데 이건 "가짜로 돌린다"는 뜻이 아니다. 로컬 모드도 **컴파일된 진짜 회로를 실행**한다. 중복 거부·한도 초과·소유권 위조가 전부 실제 회로의 `assert`에서 걸린다. 차이는 그게 네트워크를 안 탄다는 것뿐이다.

**작업의 90%는 여기서 한다.** 화면 고치기, API 수정, 테스트 추가, 버그 잡기 — 전부 지갑 없이 된다.

### 지갑이 필요해지는 때

딱 두 경우다.

1. **실제 테스트넷에 트랜잭션을 내야 할 때** — A5·A6 온체인 재현, 새 배포
2. **배포된 컨트랙트에 발급 기관 권한으로 뭔가 할 때** — 채권 추가 발행 등

이 두 가지가 아니면 §4는 건너뛰어도 된다.

## 2. 기술 스택 — 무엇을 알아야 하나

| 레이어 | 기술 | 알아야 하나 |
|---|---|---|
| 프론트 | **Next.js 15** (App Router) + TypeScript | 써봤으면 바로 시작 가능 |
| 백엔드 | **NestJS** + TypeScript | 컨트롤러·서비스·DI만 알면 됨 |
| 컨트랙트 | **Compact** (Midnight 전용 언어) | **처음일 것이다. 아래 참조** |
| 패키지 관리 | pnpm 워크스페이스 (모노레포) | |
| 테스트 | Vitest | |

**전부 TypeScript다.** Compact도 TypeScript 문법을 닮았다.

### Compact가 낯선 이유

Compact는 Midnight 전용 스마트컨트랙트 언어다. 컴파일하면 영지식 회로가 나온다.

```ts
export circuit finance(lender: Bytes<32>, amount: Uint<64>): [] {
  const inv = invoiceWitness();              // 비공개 입력
  assert(merkleVerify(leaf, path, root));    // 검증
  ledger.usedNullifiers.insert(nf);          // 공개 상태 변경
  disclose(nf);                              // 공개할 것 명시
}
```

TypeScript 같아 보이지만 다른 점이 세 가지다.

1. **witness** — 비공개 입력을 가져오는 함수. 이 값은 증명에만 쓰이고 밖으로 안 나간다
2. **ledger** — 온체인 공개 상태. 여기 쓴 건 전부 보인다
3. **disclose()** — witness에서 유도한 값을 공개 상태로 넘길 때 **반드시** 호출해야 한다. 안 하면 **컴파일이 실패한다**

3번이 이 언어의 핵심이다. 비공개성이 개발자 규율이 아니라 컴파일 오류로 강제된다.

### 회로를 안 건드리면 Compact를 몰라도 된다

`contracts/managed/`에 컴파일 결과가 커밋돼 있어서 컴파일러 설치도 필요 없다. 화면·API·테스트 작업은 전부 TypeScript다.

### 어디를 고치면 어디가 바뀌나

```
화면 고치기         apps/web/src/                Next.js
API 고치기          apps/api/src/                NestJS
검증 규칙 고치기     contracts/src/once.compact   ← Compact. 재컴파일 필요
해시 계산 고치기     packages/crypto/             ← 회로와 반드시 같아야 함
```

`packages/crypto`를 고치면 회로도 같이 고쳐야 한다. 둘이 다른 해시를 쓰면 **모든 증명이 실패하는데 원인 추적이 어렵다.** 라운드트립 테스트가 이걸 막는다.

## 3. 용어 — 모르면 §4에서 막힌다

| 용어 | 뜻 |
|---|---|
| **지갑** | 개인키를 보관하고 서명하는 프로그램. 여기서는 브라우저 확장(Lace · 1am 등) |
| **니모닉 / 시드 구문** | 영단어 12~24개. 개인키를 사람이 옮길 수 있게 만든 형태. **이걸 아는 사람이 곧 지갑 주인이다** |
| **주소** | `mn_addr_preprod1...` 로 시작. 계좌번호에 해당. 공개해도 된다 |
| **테스트넷 (Preprod)** | 진짜 돈이 없는 연습용 네트워크 |
| **faucet** | 테스트넷 토큰을 공짜로 주는 웹페이지 |
| **tNIGHT** | Preprod의 기본 토큰. 이걸 들고 있어야 DUST가 생긴다 |
| **DUST** | 트랜잭션 수수료. 다른 체인의 가스에 해당. **NIGHT를 등록하면 시간에 따라 저절로 생긴다** |
| **proof server** | 영지식 증명을 만들어주는 서버 |
| **회로 (circuit)** | Compact로 쓴 검증 로직 |
| **증명키 (prover key)** | 증명을 만들 때 필요한 파일. 저장소에 커밋돼 있다 |
| **nullifier** | 채권의 지문. 같은 채권이면 항상 같은 값. 한 번 찍히면 재사용 불가 |
| **commitment** | 봉인된 봉투. 내용을 숨기면서 고정한다 |

## 4. 지갑을 처음부터 만들기

> 원래 개발자의 지갑은 구글 계정으로 만들어져서 **니모닉을 넘길 수 없다.** 네 지갑을 새로 만들어야 한다. 그 결과가 §5의 문제로 이어지니 먼저 읽어라.

### 4.1 지갑 설치

Chrome 웹스토어에서 Midnight 커넥터 지갑을 설치한다 (Lace, 1am 등). 앱은 키 이름에 의존하지 않고 `window.midnight`를 열거해서 찾으므로 어느 쪽이든 잡힌다.

> ⚠️ **지갑 확장은 하나만 설치한 프로필에서 작업해라.** 연결 코드가 주입된 것 중 첫 번째를 무조건 고르고 선택 UI가 없다. 두 개가 깔려 있으면 열거 순서가 결정하는데 그건 제어할 수 없고, 엉뚱한 지갑에 붙으면 주소·네트워크는 멀쩡해 보이는데 서명 단계에서만 어긋난다.

### 4.2 지갑 만들기

새 지갑을 만들고 **복구 구문(니모닉)을 반드시 따로 적어 둔다.**

만들 때 방식을 고를 수 있으면 **니모닉 방식으로 만들어라.** 소셜 로그인으로 만들면 나중에 다른 기기나 다른 사람에게 넘길 수 없다. 지금 이 인수인계가 그래서 복잡해졌다.

### 4.3 네트워크를 Preprod로

설정에서 네트워크를 **Preprod**로 바꾼다. 안 하면 `Network ID mismatch`로 거부된다.

### 4.4 tNIGHT 받기

1. `pnpm dev` → `http://localhost:3040/devtools`
2. **지갑 연결** → 팝업 승인
3. 패널에 뜬 주소 복사
4. https://faucet.preprod.midnight.network/ 에 붙여넣고 요청
5. 2~3분 뒤 잔액 확인 (5,000 tNIGHT 정도)

`Services are currently unavailable`이 뜨면 서버 쪽 문제다. 5~10분 뒤 재시도하거나 Midnight Discord `kr-chat`에 물어봐라.

### 4.5 DUST 등록 — 안 하면 트랜잭션을 못 낸다

tNIGHT만 있으면 아무것도 못 한다. 수수료용 DUST가 필요하고, DUST는 **NIGHT를 등록해야** 생긴다. 지갑 확장에 이 기능의 UI가 없어서 트랜잭션을 직접 조립한다.

**스크립트가 아니라 화면의 버튼이다.**

1. `pnpm dev:preprod` → `http://localhost:3040/devtools`
2. **지갑 연결**
3. `수수료 자원 (DUST)` 이 `0 / 0` 이면 그 아래에 **[DUST 생성 등록]** 버튼이 나타난다. **DUST가 0일 때만 나온다**
4. 누르면 지갑 승인이 **2회** 뜬다 — night 검증키를 얻기 위한 버리는 서명 1회, 실제 등록 서명 1회
5. 단계 로그 8줄이 찍힌다. **[로그 복사]** 로 그대로 가져올 수 있다
6. 성공하면 마지막 줄이 `등록 후 DUST · balance=… cap=…` 이고 둘 다 0이 아니다

조립 코드는 `apps/web/src/shared/wallet/dust-registration.ts`, 원리와 실측은 `docs/SPIKE.md` §S6-f (cap 0 → 2.5e19). 이전 등록은 tx `93d62a1a…` · 블록 2605723 (`apps/deploy/deployment.json`).

**실패하면 8줄 중 어디서 멈췄는지가 곧 원인이다.** 특히 Lace가 아닌 지갑을 쓸 때 이 표가 진단이 된다.

| 마지막으로 찍힌 줄 | 죽은 지점 | 뜻 |
|---|---|---|
| (아무것도 없음) | `getDustAddress` 등 | 이 지갑은 읽기 메서드부터 다르다 |
| `NIGHT 잔액` | `signData` | keyType `unshielded` 서명을 지원하지 않는다 |
| `night 검증키 확보` | 응답에 `verifyingKey` 없음 | 서명할 바이트를 만들 수 없다 |
| `트랜잭션 조립` | `getProvingProvider` | 지갑에 증명 위임 경로가 없다 |
| `증명 완료` | `balanceUnsealedTransaction` | **여기서 막히면 A5·A6도 못 한다** |
| `잔액 조정 완료` | `submitTransaction` | 제출 경로가 없다 |

**이 버튼 하나가 A5·A6이 쓰는 쓰기 경로 전체의 사전 점검이고, 채권을 한 장도 쓰지 않는다.** 온체인 공격 재현 전에 반드시 여기를 먼저 통과해라.

> DUST 관련해 확인하지 못한 것이 있다. 인덱서의 dust 쿼리는 Cardano reward 주소 기준인데 우리는 Midnight 측 `DustRegistration`으로 등록했고 그게 동작했다. 두 경로의 관계는 모른다. `docs/SPIKE.md` §S6-f 참조.

## 5. ★ 발급 기관 키 — 인수인계의 핵심

**이 절을 건너뛰면 §4를 다 해도 배포된 컨트랙트에서 채권을 발행할 수 없다.**

### 무슨 일이 일어나는가

발급 기관 비밀키는 **브라우저 IndexedDB에만** 있다. 서버도 모르고, 지갑 니모닉과도 **전혀 다른 값**이다.

배포된 컨트랙트에는 그 키의 공개키(`0xcc56…5e72`)가 박혀 있고, 회로가 이걸 검증한다.

```
assert(issuerPublicKey(issuerSecret()) == issuerPk)
```

네가 새 브라우저에서 앱을 열면 **새 키가 생성된다.** 그 키는 `0xcc56…5e72`와 안 맞아서 채권 발행·승인이 전부 이 assert에서 실패한다. 기동은 멀쩡하고 그 호출만 죽는 형태라 원인 찾기가 어렵다.

### 해결: 키 파일을 import한다

별도로 전달받은 `once-issuer-key-52a72d93.json`을 쓴다. **저장소에 커밋하지 마라.** `.gitignore`에 `once-issuer-key-*.json`이 들어 있다.

```
/devtools → 발급 기관 키 → [가져오기] → JSON 선택
```

import하면 온체인 `issuerPk`와 대조해서 일치 여부가 바로 뜬다. 안 맞으면 다른 컨트랙트용 키다.

**받았으면 안전한 곳에 복사해 둬라.** 브라우저 데이터를 지우면 그 컨트랙트의 발급 권한이 영구 소실된다. 되살릴 방법이 없다.

### 새로 배포하고 싶다면

`/devtools`에서 배포를 새로 하면 네 브라우저의 키로 새 컨트랙트가 올라간다. 초기 설정 트랜잭션 8건, 각각 지갑 승인 1회, 총 5분 정도다.

대신 **README §5의 컨트랙트 주소와 tx 해시를 전부 새 값으로 바꿔야 한다.** 제출 직전이면 하지 마라.

## 6. 화면 구조

```
/           실제 앱. 지갑 연결 → 주소로 역할 판별 → 그 역할의 화면
/supplier   납품업체 — 자금 조달
/lender/:id 금융사 — 여신 심사
/issuer     발급 기관 — 채권 발행
/ledger     공개 원장 (지갑 불필요)
/console    발표용 3분할 데모 콘솔
/devtools   검증 도구 — 배포 · 공격 재현 · 초기화 · 발급자 키
```

`/console`과 `/devtools`는 제품이 아니다. 발표와 검증용이라 데모처럼 생긴 게 맞다. 실제 앱은 `/`에서 시작하고 거기엔 공격 버튼이 없다.

### 두 가지 실행 모드

`CHAIN_MODE` 하나로 갈린다. 기본값은 `local-circuit`이다.

| | `local-circuit` (기본) | `preprod` |
|---|---|---|
| 원장 | 프로세스 안의 컴파일된 회로 | Midnight Preprod |
| 서명 | 서버가 한다 | **사용자 지갑이 한다. 서버는 키가 없다** |
| tx 해시 | 시뮬레이터 번호 | 진짜 값, 탐색기 링크가 열린다 |
| 지갑 필요 | ❌ | ⭕ |

`preprod`에서 서버가 서명하려 하면 `SERVER_CANNOT_SIGN`으로 막힌다. 이건 버그가 아니라 의도된 동작이다. 체인에 쓰는 경로는 전부 **prepare → 브라우저 증명·지갑 서명·제출 → confirm** 구조로 되어 있고, 서버는 confirm 보고를 그대로 믿지 않고 **원장을 읽어 대조한 뒤에만** 기록한다.

새 쓰기 경로를 추가하면 `test/contract-tests/write-paths.spec.ts`가 가드 여부를 검사한다.

## 7. 남은 것

### 7.1 A5·A6 온체인 재현 ← 제일 중요

로컬에서는 통과하지만 **실제 네트워크에서는 아직 안 돌렸다.**

- **A5 (동시 신청)**: 한 채권으로 두 금융사가 동시에 신청. 실제 노드에서 두 트랜잭션이 경합할 때도 하나만 확정되는지. **이게 제품 주장 그 자체다.** 여기서 둘 다 통과하면 제품이 무너진다.
- **A6 (지연 제출)**: 미사용 시점에 만든 증명을 사용 후에 제출

`/devtools`의 **실제 체인 공격 재현** 섹션에 버튼이 있다. 각각 지갑 승인 2회, 한 건당 30~45초.

판정이 세 갈래인 걸 알아 둬라. **통과 / 실패 / 판정 불가.** 지갑 문제로 죽은 건 통과로 세지 않는다. 그 구분이 없으면 아무것도 시험하지 않고 초록불이 켜진다.

누르고 나면 원장에 실제 대출이 찍히고 tx가 탐색기에서 열린다. 지금 원장에 대출이 0건인 이유가 이거다.

### 7.2 그 외

- 데모 영상 녹화 — **미착수.** 라이브 시연은 하지 마라 (§11)
- 발표 자료 — **미착수**
- Midnight Academy 3단계 수료증 — **미착수.** 원 개발자 계정 기준이 불명이라 인수자 계정으로 새로 수료해야 한다 (심사 보너스)

## 8. AI 에이전트와 일하는 규칙

이 프로젝트는 대부분 에이전트가 짰다. 이어서 쓸 때 지킬 것.

### 8.1 Compact는 반드시 도구를 붙여라

Compact는 학습 데이터가 거의 없고 버전마다 문법이 바뀐다. 그냥 시키면 **존재하지 않는 API를 자신 있게 쓴다.**

```bash
curl -fsSL https://midnightntwrk.expert/install.sh | bash
```

설치 후 Claude Code를 재시작하고 `/midnight-expert:doctor`로 환경을 점검한다. `midnight-awesome-dapps` 레포와 공식 Docs도 컨텍스트에 넣어라.

### 8.2 "통과했다"를 그대로 믿지 마라

이 프로젝트에서 실제로 네 번 터졌다.

- `pnpm build`가 루트에 스크립트가 없어서 "no build script"로 끝나는데 **"빌드 통과"로 보고**됐다
- witness 경로 버그 때문에 A3·A4가 타입 오류로 죽고 있었는데 **초록불이었다.** 검증하려던 검사를 통과한 적이 없었다
- 공격 러너가 서버 서명 실패를 "막혔다"로 세어 **여섯 칸 전부 통과**를 띄웠다. 아무것도 시험하지 않은 채로
- 콘솔의 A5가 **결과를 보지 않고** 통과를 써 넣고 있었다

**무엇을 어떻게 검증했는지 물어봐라.** "테스트 통과"가 아니라 "이 테스트가 무엇을 확인하는가".

그래서 이 저장소의 거부 테스트는 "거부됐다"가 아니라 **"의도한 assert에서 거부됐다"**를 확인한다.

### 8.3 제품을 없애는 제안을 걸러라

| 제안 | 왜 안 되나 |
|---|---|
| "조회 API로 단순화하자" | INV-3이 사라진다. 조회와 송금 사이의 틈이 이 제품이 없앤 바로 그 구멍이다 |
| "nullifier에 salt를 섞자" | 같은 채권을 무한 재사용할 수 있게 된다 (INV-1) |
| "사전 조회가 있으니 컨트랙트 검사는 중복이다" | 사전 조회는 UX용이다. 진짜 방어는 실행 시점 검사다 |
| "Compact 0.34로 올리자" | ledger 9 타깃이라 배포가 불가능해진다 |
| "업그레이더블 프록시로 만들자" | 같은 주소에서 코드 교체가 가능하면 전제가 무너진다 |
| 상환·이자·KYC·신용평가 추가 | README §9 "이 프로젝트가 아닌 것" 참조 |

### 8.4 무거운 작업엔 자원 제한

지갑 동기화가 CPU 4코어·4GB를 26분 물고 머신이 뜨거워진 적이 있다. `nice`와 `taskpolicy`는 효과가 없었고 **스레드 수 제한**이 실제로 잡았다.

```bash
UV_THREADPOOL_SIZE=2 node --v8-pool-size=2 ...
```

프로세스를 죽일 때 래퍼만 죽이면 자식이 살아남는다. `scripts/stop-all.sh`를 써라.

## 9. 함정 — 실제로 여기서 터졌다

### 버전 고정을 풀지 마라
Compact 0.31.1 / language 0.23 / runtime 0.16.0. 세션 훅이 0.34 업그레이드를 권하는데 **하면 배포가 안 된다.** `docs/VERSIONS.md`에 이유가 있다.

### 패키지 중복 설치
`@midnight-ntwrk` 패키지가 두 버전으로 깔리면 **WASM이 두 인스턴스로 뜨고 조용히 실패한다. 빌드는 통과한다.** 실제로 `ledger-v8`(8.1.0/8.1.2)과 `onchain-runtime-v3`(3.0.0/3.1.1)에서 터졌다.

`pnpm-workspace.yaml`의 `overrides`로 고정돼 있고 `test/contract-tests/single-runtime.spec.ts`가 락파일·설정·잔재를 대조한다. 이 테스트가 깨지면 무시하지 마라.

> 고정이 사는 곳이 한 번 바뀌었다. pnpm 10부터 `package.json`의 `pnpm` 필드를 읽지 않는다. 옮기기 전까지 경고 한 줄만 나오고 고정이 조용히 풀려 있었다.

### 브라우저 확장이 요청을 삼킨다
광고·프라이버시 확장 중에 웹페이지가 **localhost의 다른 포트로 보내는 요청**을 포트 스캔으로 보고 막는 것들이 있다. 거부도 CORS 오류도 아닌 **무응답**이라 화면이 `—`인 채로 멈추고 서버 로그에 아무것도 안 남는다.

Next.js rewrite로 `/api/*`를 같은 출처로 프록시해 해결했다. **이 구조를 되돌리지 마라.**

### 기본값이 상태를 감춘다
`simulated={status?.simulated ?? true}` 때문에 체인 응답이 오기 전에 실행 불가능한 버튼들이 활성으로 떴다. **로딩 중과 확정된 상태를 구분해라.** 모르는 상태에서는 아무것도 보여주지 않는 쪽이 맞다.

### 비밀값에 기본값을 넣지 마라
발급자 비밀키에 소스에 적힌 더미값을 쓰면 배포 시 누구나 발급 기관 권한 회로를 부를 수 있다. A8 주장이 무너진다.

### `.env`와 Node 버전
루트 `.env`가 있는데 Node 20.12 미만이면 `process.loadEnvFile is not a function`으로 죽는다. 메시지만 봐서는 원인을 알기 어렵다. 심사 경로는 `.env` 없이 돌아서 여기 안 걸린다.

## 10. 막혔을 때

| 증상 | 먼저 볼 것 |
|---|---|
| 화면 값이 전부 `—`, 노드 끊김 | API 서버가 떴나. 브라우저 Network 탭에 요청이 나가나 |
| 빌드 ENOENT | 패키지 중복. `pnpm-workspace.yaml`의 `overrides` 확인 후 클린 재설치 |
| `Network ID mismatch` | 지갑 네트워크가 Preprod인가 |
| 증명 생성 실패 | proof server가 떴나 (`docker ps`) |
| `SERVER_CANNOT_SIGN` | preprod에서 서버 서명은 막혀 있다. 브라우저 경로로 가야 한다 |
| `CLAIM_NOT_ON_CHAIN` | 체인에 안 올라간 걸 올라갔다고 보고했다. 정상 동작이다 |
| 채권 발행이 assert 실패 | **발급 기관 키 문제다. §5를 읽어라** |
| 트랜잭션이 안 나감 | DUST 등록했나 (§4.5) |
| 신청만 실패하고 기동은 멀쩡 | `.env.preprod`의 공급자 키가 배포에 쓰인 키와 다른지 확인 |
| 테스트는 통과하는데 동작이 이상 | 그 테스트가 무엇을 검증하는지 읽어봐라 |

## 12. 넘겨받는 사람에게

화면이 초록불이어도 아무것도 시험하지 않았을 수 있다. 실제로 네 번 그랬다. 그래서 테스트가 "거부됐다"가 아니라 "**의도한 assert에서** 거부됐다"를 확인하고, 공격 판정이 "통과/실패" 둘이 아니라 "**판정 불가**"를 포함한다.

기능을 추가할 때도 같은 기준으로 봐라. **그 기능이 동작하는 걸 무엇으로 확인했는가.**
